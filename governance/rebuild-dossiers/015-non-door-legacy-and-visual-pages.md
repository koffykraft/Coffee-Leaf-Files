## 5. `buna-visual-guide.html`

Current page explicitly states that its charts are theoretical simulation models used to demonstrate interface behaviour rather than independent clinical data.

It nevertheless renders values such as:
- Water Control 49.7;
- Oolong-Style 19.1;
- emotion-recognition profiles and L-theanine comparison.

Even with the disclaimer, visually precise bars and numbers can be mistaken for study results, especially if a screenshot is detached from the note.

Disposition: **ARCHIVE / RETIRE FROM PUBLIC KNOWLEDGE LAYER.**

If useful as a UI mockup, preserve it in design history or a non-public prototype area. Do not migrate the numerical simulation into the rebuilt site.

Future visualizations must be generated from verified data objects and carry source/context with the graphic.

## 8. `vocab/board-thermal-transformation.html`

This board demonstrates why visual pages require the same message audit as prose.

It turns a cautious pattern from the text vocabulary into emphatic language:

- extended wet heat `increases sweetness and decreases bitterness`;
- described as `the single most important thermal fact`;
- says Kuti and Engere `rely on this principle`;
- presents specific wet-heat stages and outcome claims visually as established operating rules.

This is stronger than the corresponding textual page, which already says the pattern should not be stated as a universal law.

Disposition: **RETIRE AS CURRENT KNOWLEDGE PAGE / PRESERVE AS DESIGN SOURCE UNTIL REPLACED.**

Future thermal visualization must be generated from the audited Door Three/Four evidence model and must show scope/uncertainty with the same prominence as temperature values.

## 9. General rule for visual boards

A visual board is not permitted to simplify uncertainty away.

Rebuild requirement:

**Accepted claim/data object → textual explanation and visual representation derive from the same source.**

A visual cannot:
- introduce a new mechanism;
- strengthen a qualifier;
- convert `may` into `does`;
- turn one producer/study value into a universal value;
- invent numerical simulation without unmistakable prototype context;
- carry stale copies of tradition facts.

## 10. Legacy-route architecture

Legacy URLs should be separated from current page architecture.

Conceptual categories:

- **CURRENT CONTENT** — part of the rebuilt knowledge system.
- **LEGACY REDIRECT** — resolves old bookmarks but is never indexed/navigated.
- **ARCHIVE SOURCE** — preserved in repository/history, not public reader journey.
- **PROTOTYPE/DESIGN SOURCE** — useful for UI history, not knowledge publication.

The rebuilt Catalogue and page counts should count current content only.
