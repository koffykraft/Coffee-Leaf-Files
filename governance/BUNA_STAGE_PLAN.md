# Buna Structural Repair Stages

This file records the staged order. Stage numbers are control gates, not deadlines.

## Stage 0 - Control, baseline and examination rules

Status: IMPLEMENTED

- freeze baseline
- dedicated repair branch
- full-site audit tooling
- two independent full examinations after every correction unit
- repair ledger
- final structural system audit reserved
- later validity and honesty audit reserved

## Stage 1 - Isolate conflicting legacy health material

Purpose: prevent old ungoverned health/lifestyle pages from competing with Door Nine while preserving URLs safely.

No substantive validity certification is performed here. That remains for the later content audit.

## Stage 2 - Repair definite broken links

Priority:

- Door Eight `doc/obs/trad/hyp` pseudo-links
- misplaced vocabulary icon-board routing
- wrong relative Chemo link
- homepage missing Catalogue fragment
- decide and resolve `buna-in-kerala.html`

## Stage 3 - Repair canonical navigation hierarchy

- remove ordinary navigation through `visitor-lounge.html`
- correct `begin-with-a-cup.html` tradition entry routes
- review tool links that enter tradition families midstream
- normalize parent/back/breadcrumb destinations

## Stage 4 - Classify hidden and orphaned pages

Every zero-incoming or effectively orphaned page receives one status:

CURRENT / LEGACY REDIRECT / ARCHIVE / REPAIR / SURFACE / RETIRE

No mass deletion and no automatic surfacing.

## Stage 5 - Complete Door inventories

Priority Doors: Two, Three and Eight.

Each Door landing/library map branch must accurately represent all current material assigned to that Door.

## Stage 6 - Rebuild Catalogue as complete site map

Bring Catalogue into agreement with the nine-Door structure and include all current major resources without becoming a duplicate of every local page index.

## Stage 7 - Clean structural shell and platform debt

- source-level duplicate header cleanup
- semantic titles/H1s
- stale wording/contact checks
- move legacy Netlify-shaped calls to canonical neutral API routes
- retain compatibility routes only where required

## Stage 8 - Final structural system audit

Fresh clean-checkout audit of the entire site after all repair stages.

No structural completion claim until this passes.

## Stage 9 - Reserved validity and honesty audit

A separate evidence/content program after structure is accepted.

It will test source support, evidence level, wording, uncertainty, historical/cultural traceability, conflicts, overclaiming and the distinction between published evidence, traditional report, Citane observation and hypothesis.
